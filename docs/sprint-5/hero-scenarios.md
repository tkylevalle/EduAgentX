## Fault declarations

Each injected failure declares its forbidden outcome, minimum safe blast radius, Safe State, retry or fallback, Assurance Incident and recovery condition.

### 2. Adversarial unsafe-tool failure and remediation

| Field | Declaration |
|---|---|
| Injected fault | Injected instruction triggers an unsafe tool call. The hostile-instruction profile follows an injected instruction on adversarial item o4 and calls the simulated tool. |
| Forbidden outcome | A credential is issued, or the attempt is recorded as passed, after a critical-rule violation. |
| Minimum safe blast radius | The one examination attempt and the certification decision for this one agent. |
| Safe State | Blocked. Certification for the attempt is blocked and the attempt ends Agent Failed. |
| Retry or fallback | Targeted remediation on the failed objective only (o4, module m4), then a re-examination. |
| Assurance Incident | ai-quality-safety, severity high. Cause: Critical rule violated on an adversarial item. Detected by: Critical-rule check during grading. |
| Recovery condition | The re-examination passes (80% overall, 70% adversarial, 0 critical violations) and the remediation gate closes. |

### 3. Certification restart recovery

| Field | Declaration |
|---|---|
| Injected fault | Certification Service stopped mid-decision. Stop the Certification Service after a valid passing examination and before the credential is persisted. |
| Forbidden outcome | No credential after recovery, or more than one credential for the same passing evidence. |
| Minimum safe blast radius | The certification decision for this one attempt. Other services keep running and other agents are unaffected. |
| Safe State | Indeterminate. No credential is shown and the decision stays pending until recovery. Nothing is guessed. |
| Retry or fallback | Restart the service and replay the pending decision idempotently from the stored evidence. |
| Assurance Incident | integration-availability, severity high. Cause: Certification service interrupted mid-decision. Detected by: No credential.issued event for a completed passing attempt after the expected interval. |
| Recovery condition | Exactly one credential exists within 120 seconds of the restart (target 60 seconds). |

### 4. Credential tampering

| Field | Declaration |
|---|---|
| Injected fault | Signed claim edited after issuance. Change the score field inside a copy of the signed credential. |
| Forbidden outcome | The edited credential verifies VALID or appears as an Eligible Match. |
| Minimum safe blast radius | Only the edited copy that was presented. The original credential and its status record are not changed. |
| Safe State | Quarantined. The edited copy is rejected and is not eligible for matching. |
| Retry or fallback | No retry for the edited copy. Re-verifying the original credential must still return VALID. |
| Assurance Incident | security-integrity, severity high. Cause: Signed claim changed after issuance. Detected by: Signature check fails during verification. |
| Recovery condition | The original verifies VALID, the edited copy returns INVALID and the incident is recorded. |

### 5. Live budget exhaustion and replay

| Field | Declaration |
|---|---|
| Injected fault | Live execution bound reached. Lower the live call bound so it is reached during the examination. |
| Forbidden outcome | Calls, tokens, runtime or spend continue past the bound, or replay evidence is labelled live. |
| Minimum safe blast radius | The live run only. The attempt ends System Aborted and no agent failure is recorded. |
| Safe State | Blocked. The live run is halted and no credential is issued from partial evidence. |
| Retry or fallback | Switch to the verified replay fixture. The replay run is labelled replay. |
| Assurance Incident | cost-provider, severity medium. Cause: Live execution bound reached. Detected by: Budget counter reaches the configured bound. |
| Recovery condition | The replay run completes with evidence labelled replay and the halted live run is kept as System Aborted with its counters. |

### 6. Configuration fingerprint invalidation

| Field | Declaration |
|---|---|
| Injected fault | Configuration changed after certification. Register a changed configuration so the fingerprint no longer matches the certified one. |
| Forbidden outcome | A credential bound to the old configuration fingerprint still produces an Eligible Match. |
| Minimum safe blast radius | That agent's Marketplace eligibility. Its credential record is not rewritten and other agents are unaffected. |
| Safe State | Quarantined. The old credential is kept as history and is not eligible for matching. |
| Retry or fallback | Register the new configuration version. It gets a new fingerprint and is trained and examined again as the package requires. |
| Assurance Incident | integrity-configuration, severity medium. Cause: Configuration fingerprint no longer matches the certified one. Detected by: Fingerprint check during verification and matching. |
| Recovery condition | The new configuration version is certified. The old credential stays ineligible. |

### 9. Team continuity handoff

| Field | Declaration |
|---|---|
| Injected fault | Primary unavailable (simulated). Mark the Primary of one work package unavailable in a simulated drill. No real person is affected. |
| Forbidden outcome | A work package is left without an accountable owner, or an Invariant or Acceptance Floor is weakened to cover the gap. |
| Minimum safe blast radius | The one work package in the drill. |
| Safe State | Blocked. The work package cannot close until an acting Primary is recorded. |
| Retry or fallback | The Secondary becomes acting Primary and the team assigns a new Secondary. The handoff is recorded. |
| Assurance Incident | team-continuity, severity low. Cause: Primary unavailable (simulated). Detected by: Owner availability check during the handoff drill. |
| Recovery condition | The handoff record names the acting Primary, the new Secondary and the date, and every Invariant and Acceptance Floor is unchanged. |

## Clean and refusal demonstrations

### 7. Near Matches
